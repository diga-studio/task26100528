# 部门风险趋势统计库（risk）

单部门钓鱼识别能力分的进程内存统计库，供上层报表直接调用。
支持乱序补录与覆盖历史测评，查询任意历史区间的持续时间加权
平均分与高风险（部门分严格低于 50）累计秒数。

## 语义

- 统计范围固定为 `[start, start+365天)`，期间员工与权重不变。
- 任意时刻员工的有效分数 = 该时刻之前或恰好该时刻生效的最新测评；
  没有后续测评时沿用起点分数。补录只影响其生效秒到该员工下一条
  测评之前的状态。
- 部门能力分 = 所有员工有效分数按固定权重的加权平均；
  严格低于 50 为高风险，恰好等于 50 不计入。
- 同一员工、同一生效时间的再次写入覆盖原分数；初始装载中出现
  重复时以靠后的记录为准。
- 查询为左闭右开区间，自动裁剪到统计范围；所有变化从生效秒起算，
  不按天抽样、不对分数取整。

## 使用

```go
emps := []risk.Employee{
    {ID: "alice", Weight: 3, StartScore: 72},
    {ID: "bob",   Weight: 1, StartScore: 45},
}
tr, err := risk.NewTracker(startUnix, emps, initialAssessments)
if err != nil { /* 参数非法 */ }

// 补录或覆盖（任意顺序到达，返回后查询立即反映）
err = tr.Upsert(risk.Assessment{EmployeeID: "bob", Time: t1, Score: 60})

// 查询 [from, to)
stats := tr.Query(from, to)
fmt.Println(stats.Average, stats.HighRiskSeconds)
```

非法输入（空名单、重复员工、权重不在 1–100、分数不在 0–100、
未知员工、生效时间在统计范围外）会返回错误，统计器状态不变。

## 实现与复杂度

- 每名员工一棵按生效时间排序的随机平衡树（`treap.go`），
  覆盖/前驱/后继均为 O(log n)。
- 部门加权总分 S(t) 是分段常数函数；一次写入等价于对
  `[生效时间, 该员工下一条测评)` 区间加常数 δ = 权重×(新分−旧有效分)。
- 时间轴采用按段数的平方分解（`timeline.go`）：整块区间加只累加
  懒标记；块内保存按值排序的副本，低于阈值的时长经二分得到。
  写入 O(√n log n)，查询 O(√n log n)，段数 n ≤ 测评时点数。
- 高风险判定用整数比较 S < 50×总权重，秒数精确；平均分为
  int64 积分转 float64，绝对误差远低于 1e-6。

## 测试

```sh
go test ./...        # 全部测试（含规模测试）
go test ./... -short # 跳过规模测试
```

规模测试：500 名员工、100 万条初始测评（70% 集中在前 30 天，
10 名员工全年只有起点分并被反复补录覆盖），交错 1 万次查询与
2000 次写入。实测交错阶段约 0.55 秒，堆内存约 120 MiB
（上限分别为 15 秒、256 MiB）。
